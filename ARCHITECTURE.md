# Architecture

Where things are and how a request is answered. Setup, commands and deploy are
in [README.md](README.md). Paths are relative to the repository root.
Statements are read from the named file. The block marked "Observed" in
"Caching" is a dated observation of the production site, with the command
used; the repository cannot confirm it.

The frontend is a Nuxt app in `frontend/` (versions: `frontend/package.json`),
the backend is Drupal in `drupal/` (versions: `drupal/composer.json`). The
directory layout is in [AGENTS.md](AGENTS.md).

## Request path

### Production

- Lagoon routes the hostnames listed under `routes` in `.lagoon.yml` to the
  `nginx` service of `docker-compose.yml`.
- `.lagoon/nginx-lagoon.conf` answers a request itself, or sends it to Nuxt
  (`@frontend`, `frontend:3000`) or to Drupal (`@drupal`, php-fpm):

| Path                                                             | Answer                          |
| :--------------------------------------------------------------- | :------------------------------ |
| The `www` hostname (second `server` block)                       | 301 to the bare hostname        |
| `/article/<slug>`                                                | 301 to `/news/<slug>`           |
| Dotfiles except `/.well-known`                                   | Denied                          |
| Files ending in `md`, `txt`, `yml`, `yaml`, `lock`, `dist`       | Denied, with exemptions (below) |
| `update.php`, `core/install.php` and other `.php` entry points   | 404                             |
| `/graphql`                                                       | Drupal                          |
| The admin and system prefix list (`user`, `admin`, `media`, ...) | Drupal                          |
| `node/add`, `node/<id>/edit` and the other entity form routes    | Drupal                          |
| `/news/planet_drupal.xml`                                        | Drupal                          |
| `/sites/default/files`                                           | File on disk, else Drupal       |
| Static file extensions (`js`, `css`, images, fonts)              | File in the docroot, else Nuxt  |
| `/robots.txt`                                                    | Nuxt (`frontend/public/`)       |
| Other paths (`location /`)                                       | File in the docroot, else Nuxt  |

- The file is the reference for the order and exact patterns of the rules.
- The extension rule exempts `system/files` and `/.well-known/`, and does not
  apply under `/sites/default/files`, which has its own location.
- A new Drupal route under a new prefix needs an entry in the prefix list.

### Local (DDEV)

- `.ddev/nginx_full/nginx-site.conf` also splits between Nuxt (`@frontend`,
  `localhost:3000`) and Drupal (`@drupal`, `localhost:8888`). Its rules are
  not the Lagoon rules. Examples: it redirects `/` by `Accept-Language`, has
  no `/article` redirect, sends `/api` to Nuxt and `/drupal-api` to Drupal by
  their own rules, and its Drupal prefix list has entries the Lagoon list
  lacks (`tfa`, `multi-site`) and lacks others (`file/<id>/delete`,
  `.well-known/change-password`).
- It is generated by `scripts/nginx-conf-generator/index.js` from
  `scripts/nginx-conf-generator/config/base.yml` with
  `scripts/nginx-conf-generator/config/ddev.yml` merged over it. The same run
  writes `lando/nginx/custom.conf` and `deploy/nginx/ci/ci.conf`.
  Regenerating: [README.md](README.md), section "Routing".
- `.lagoon/nginx-lagoon.conf` is written by hand, not generated.

## How Nuxt gets data

- Module: `nuxt-graphql-middleware`, configured in
  `frontend/config/graphqlMiddleware/index.ts`.
- Operations are `.graphql` files next to the component or page that uses
  them, named `query.<name>.graphql`, `fragment.graphql` or
  `fragment.<name>.graphql`. Shared ones are in `frontend/app/queries/`; two
  files there, `blokkli.graphql` and `translations.graphql`, do not follow
  the naming. The module collects the files matched by `autoImportPatterns`.
- The browser and the server renderer both call
  `/api/graphql/query/<operation name>` on the Nuxt server. Nuxt forwards the
  operation to Drupal's `/graphql`.
- Server side of that call: `frontend/server/graphqlMiddleware.serverOptions.ts`.
  App side: `frontend/app/plugins/graphqlMiddleware.ts`.
- `frontend/schema.graphql` is the Drupal schema. A build reads it from
  disk; the dev server downloads it from the backend (see
  [AGENTS.md](AGENTS.md)).
- A route page asks Drupal what a path is with the `route` query
  (`frontend/app/pages/[...slug]/query.route.graphql`,
  `frontend/app/queries/fragment.routeQuery.graphql`) and passes the result to
  vuepal's `useDrupalRoute`, which handles redirects, metatags and the 404.
- Menus and other site-wide data: `frontend/app/composables/useInitData.ts`.
- Interface texts: `nuxt-easy-texts` (`easyTexts` in
  `frontend/nuxt.config.ts`).

## Page rendering

| Route file                                           | Renders                                              |
| :--------------------------------------------------- | :--------------------------------------------------- |
| `frontend/app/pages/index.vue`                       | Home. Queries the path `/home`.                      |
| `frontend/app/pages/[...slug]/index.vue`             | Any Drupal path: `Node/Page` or `Node/Page/Landing`. |
| `frontend/app/pages/news/index.vue`                  | News list with `?page=`.                             |
| `frontend/app/pages/news/[...slug]/index.vue`        | One news article (`Node/PressRelease`).              |
| `frontend/app/pages/node/[nid]/index.vue`            | `/node/<id>`.                                        |
| `frontend/app/pages/blokkli/library-item/[uuid].vue` | Library item in the editor; layout `library`.        |
| `frontend/app/pages/static-page/example.vue`         | Example of a page with a fixed path.                 |

The components named in the right column are under
`frontend/app/components/`.

- Layouts: `frontend/app/layouts/`. `default.vue` holds header, breadcrumb,
  main and footer.
- A Drupal paragraph type maps to a component by its machine name:
  `frontend/app/components/Paragraph/<Name>/index.vue` calls
  `defineBlokkli({ bundle: '<machine name>' })`, and the type is
  `drupal/config/default/paragraphs.paragraphs_type.<machine name>.yml`.
- Fragments are components that call `defineBlokkliFragment` in
  `frontend/app/components/Paragraph/BlokkliFragment/`. The ones editors can
  add are listed in `frontend/app/composables/pageFragments.ts`; the Drupal
  paragraph type is
  `drupal/config/default/paragraphs.paragraphs_type.blokkli_fragment.yml`.
- The build writes the paragraph options to the path in `schemaOptionsPath`
  (`frontend/nuxt.config.ts`).
- A request with a Drupal session cookie is not rendered on the server:
  `frontend/server/middleware/spa.ts`.

## Caching

- `frontend/config/multiCache/index.ts`: data cache on, CDN headers on, purge
  API on, route cache off, component cache off.
- `frontend/server/graphqlMiddleware.serverOptions.ts` adds Drupal's
  cacheability (`frontend/server/utils/cacheability.ts`) to a GraphQL response
  when the request comes from a server render, or in development.
- The page passes it to nuxt-multi-cache's CDN helper
  (`frontend/app/helpers/graphqlCacheability/index.ts`), which writes
  `CDN-Cache-Control` and `Cache-Tag`. The helper keeps the lowest max age
  and stays private once one response was private.
- The tags for `Cache-Tag` are read from Drupal's `surrogate-key` response
  header, or from `x-drupal-cache-tags`. On production Drupal sends neither:
  `drupal/composer.json` has no Fastly module, and
  `http.response.debug_cacheability_headers` is false in
  `drupal/docroot/sites/default/services.yml`. So production pages carry no
  `Cache-Tag`. A Lagoon development environment also loads
  `drupal/docroot/sites/default/development.services.yml`, which turns that
  setting on, so its pages do.
- A thrown error or a response status of 400 and above gets
  `CDN-Cache-Control: private`:
  `frontend/server/plugins/errorNotCacheable.ts`.
- Build assets, fonts and `frontend/public/images/` get their `cache-control`
  from `routeRules` in `frontend/nuxt.config.ts`.
- Files under `/sites/default/files` get one day from
  `.lagoon/nginx-lagoon.conf`.
- Drupal purges the Nuxt data cache through the `nuxt_multi_cache` purger
  (`drupal/config/default/purge.plugins.yml`). No Fastly purger is configured
  there.

Observed 2026-10-11 with
`curl -s -o /dev/null -D - https://drupalmountaincamp.ch/news`, run twice
within a second and once more six seconds later:

- `x-served-by` and `server-timing: ... fastly`: Fastly is in front of
  Lagoon. No Fastly configuration is in this repository.
- `cache-control: public, max-age=1` next to
  `cdn-cache-control: max-age=31536000, public`. Where `max-age=1` is set was
  not found in this repository.
- `x-cache` ended in `MISS`, then `HIT`, then `MISS`: the page was kept for
  about a second, so `CDN-Cache-Control` did not decide how long it was kept.

## Images

- `frontend/app/components/ImageItem/index.vue` renders the images of
  `frontend/app/components/MediaImage/index.vue`, which adds caption and
  credit. Some components write their own `<img>`, for example
  `frontend/app/components/SponsorTile/index.vue` and
  `frontend/app/components/Paragraph/Video/index.vue`.
- Drupal returns four derivatives per image
  (`frontend/app/components/ImageItem/fragment.imageItem.graphql`); they
  become the `srcset`. The styles are
  `drupal/config/default/image.style.*.yml`.
- `sizes` comes from the component when it passes one, built with
  `frontend/app/helpers/imageSizes/index.ts`. Otherwise it is capped at the
  largest width of an image style given as an object, or at the `xl`
  breakpoint for a style given by name.
- rokka renders an image only when `frontend/app/helpers/rokka/index.ts`
  allows it; otherwise the Drupal derivatives are used.

## Head and SEO

- Title, description, canonical and Open Graph defaults are Drupal config:
  `drupal/config/default/metatag.metatag_defaults.*.yml`. They reach the page
  through the route query and `useDrupalRoute`.
- The frontend adds share tags a page lacks
  (`frontend/app/helpers/shareTags/index.ts`), the home page's own canonical
  (`frontend/app/pages/index.vue`) and the `?page=` rule
  (`frontend/app/middleware/canonical-page-param.ts`).
- JSON-LD for news articles is configured in
  `drupal/config/default/metatag.metatag_defaults.node__press_release.yml`
  (`schema_article_*`). JSON-LD for the event on the home page is built in
  `frontend/app/helpers/eventSchema/index.ts`.
- The sitemap is Drupal's (`drupal/config/default/simple_sitemap.*.yml`). The
  news list has no Drupal route and is added in
  `blokkli_starterkit_simple_sitemap_arbitrary_links_alter()`
  (`drupal/docroot/modules/custom/blokkli_starterkit/blokkli_starterkit.module`).
- `robots.txt` is `frontend/public/robots.txt`. nginx adds `X-Robots-Tag` on
  Drupal's admin paths (`$admin_robots_tag` in `.lagoon/nginx-lagoon.conf`).

## Fonts, styles and design tokens

- Colours, font families and breakpoints: `frontend/tailwind.config.ts`.
  Breakpoint values: `frontend/app/tailwind/screens.ts`.
- Global CSS: `frontend/app/assets/css/tailwind.css`,
  `frontend/app/assets/css/typography.css` and
  `frontend/app/assets/css/components/`.
- Fonts: both fonts' `@font-face` rules are in
  `frontend/app/assets/css/typography.css`. The body font's files come from
  the `@fontsource-variable/source-sans-3` package, the heading font's are in
  `frontend/public/fonts/`. One file of each is preloaded:
  `HEADING_FONT_PRELOAD` and `BODY_FONT_PRELOAD` in `frontend/nuxt.config.ts`.
- `frontend/app/assets/css/backend.css` is compiled into the custom module by
  the `styles` scripts in `frontend/package.json`. The module's library loads
  it: `drupal/docroot/modules/custom/blokkli_starterkit/blokkli_starterkit.libraries.yml`.

## Drupal

- Custom code is one module:
  `drupal/docroot/modules/custom/blokkli_starterkit/`. Hooks are in its
  `.module` file, classes in `src`, tests in `tests/src`.
- Content types: `drupal/config/default/node.type.*.yml`.
- Configuration is `drupal/config/default/`. How to export and import it:
  [README.md](README.md), section "Deploy".

## Deploy

The services are in `docker-compose.yml`. Those with a `dockerfile` entry are
built from `.lagoon/Dockerfile`; `mariadb` uses a published image. The
`post-rollout` tasks in `.lagoon.yml` run on the
`cli` service: `drush updb`, `drush cr`, `drush cim`, `drush cr` and
`drush search-api:index`. The same file sets the cron job and the routes.

## Tests and CI

The four workflows run on pull requests against `prod`.

| Workflow                               | Job          | Runs                                                                |
| :------------------------------------- | :----------- | :------------------------------------------------------------------ |
| `.github/workflows/frontend-tests.yml` | `vitest`     | `bun run test:coverage`                                             |
| `.github/workflows/frontend-tests.yml` | `checks`     | lint, prettier, typecheck, build, then the font preload test        |
| `.github/workflows/drupal-tests.yml`   | `php`        | phpstan, phpcs, phpunit Unit, phpunit Kernel on the custom module   |
| `.github/workflows/nginx-config.yml`   | `nginx-test` | `nginx -t` on the Lagoon config, then `scripts/ci/nginx-headers.sh` |
| `.github/workflows/docs.yml`           | `doc-paths`  | `scripts/ci/check-doc-paths.sh`                                     |

- Frontend tests: `frontend/app/__tests__/` and
  `frontend/app/pages/__tests__/`.
- Drupal tests:
  `drupal/docroot/modules/custom/blokkli_starterkit/tests/src/`. CI runs the
  `Unit` and `Kernel` directories, not `ExistingSite`.
- The commands are in [AGENTS.md](AGENTS.md).
